# Experiment: Client-Side Testing

## Aim
To understand client-side security weaknesses in a controlled web application.

## Requirements
- Browser developer tools
- A local practice application
- Permission to inspect and modify test inputs

## Theory
Client-side testing examines browser-executed code, input handling,
DOM manipulation, security headers, and the boundary between client
and server validation. Client-side validation alone cannot enforce
security-sensitive rules.

## Procedure
1. Open the designated local application.
2. Inspect the page structure using developer tools.
3. Examine JavaScript and client-side form validation.
4. Submit valid and invalid test inputs.
5. Compare client-side validation with server-side responses.
6. Inspect relevant security headers and cookie attributes.
7. Document any reproducible issues and recommended fixes.

## Precautions
- Use a local or explicitly authorized application.
- Avoid submitting real personal information.
- Treat client-side checks as usability controls, not security boundaries.
